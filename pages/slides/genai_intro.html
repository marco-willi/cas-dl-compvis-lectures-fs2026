What is Generative Modelling?

Classification: \(f(\mathbf{x}) = \mathbf{y}\)

Many-to-one: many elephant images → one label.

Generation: \(g(\mathbf{y}) = \mathbf{x}\)

One-to-many: one label → many possible elephant images.

Quiz: The Problem

If the input is just the label “elephant”, how can the model generate different elephants?

Answer: Neural networks are deterministic. We need stochasticity.

The Diversity Challenge

A specific label should produce a diverse set of outputs.

Solution: Latent Variables

Add stochastic input \(\mathbf{z} \sim p(\mathbf{z})\):

\[\hat{\mathbf{x}} = g_{\theta}(\mathbf{y}, \mathbf{z}), \qquad \mathbf{z} \sim \mathcal{N}(\mathbf{0}, \mathbf{I})\]

Latent variable \(\mathbf{z}\) — unobserved factors:

  • pose, size, number of individuals
  • time of day, surroundings, lighting
  • \(\mathbf{y}\) → what to generate (control)
  • \(\mathbf{z}\) → how it varies (diversity)

Quiz: Latent Variables

What could the latent variables be for this dataset?

Answer: Width and height — 2 unobserved latent variables.

Latent Space → Outputs

Plausible 2D latent space and the mapping to samples (Foster (2023)).

Unconditional vs. Conditional Generation

Unconditional Generation

The model receives only stochastic input:

\[\mathbf{z} \sim p(\mathbf{z}), \quad \hat{\mathbf{x}} = g_{\theta}(\mathbf{z})\]

  • \(\mathbf{z}\) provides diversity
  • different \(\mathbf{z}\) → different plausible outputs
  • e.g. “any face”, “any room”, “any product”

Conditional Generation

The model also receives conditioning information \(\mathbf{c}\):

\[\hat{\mathbf{x}} = g_{\theta}(\mathbf{z}, \mathbf{c})\]

\(\mathbf{c}\) specifies what should be generated, preserved, completed, enhanced, or changed.

Key idea: \(\mathbf{z}\) provides diversity, \(\mathbf{c}\) provides control.

Generative CV Beyond Text-to-Image

Setting Condition \(\mathbf{c}\) Example

Creative vs. Faithful

  • Creative: unconditional, text-to-image — diversity, plausibility
  • Faithful: inpainting, super-res, translation, editing — identity, geometry, layout
  • Most real systems need both

Prompt: Create an image where this object is shown dancing in the jungle with a banana in one hand and a shampoo in the other hand.

Learning Generative Models

The Objective

Generated \(\hat{\mathbf{x}}\) should have high probability under the real data distribution \(p_{\text{data}}(\mathbf{x})\).

Two Approaches

1. Direct (Implicit)

Learn a function that generates samples directly: \[g(\mathbf{z}) = \mathbf{x}\]

2. Indirect (Density)

Learn a probability density \(p_{\theta}(\mathbf{x})\), then sample from it.

Density Models

Learn \(p_{\theta}: \mathbf{x} \to [0, \infty)\) with normalization:

\[\int_{\mathbf{x}} p_{\theta}(\mathbf{x})\, d\mathbf{x} = 1\]

Goal: \(p_{\theta} \approx p_{\text{data}}\).

Maximum likelihood objective:

\[\underset{\theta}{\arg\max} \frac{1}{N} \sum_{i=1}^{N} \log p_{\theta}(\mathbf{x}^{(i)})\]

Examples: VAEs, normalizing flows, autoregressive models.

Learning a Density Model

The model adapts to place high probability where training data lies.

Density ≠ Generation

A density model evaluates \(p_{\theta}(\mathbf{x})\) — useful for outlier detection.

To generate, we additionally need a sampling mechanism.

Desirable Properties

1. Efficient Sampling

  • Generate new samples quickly
  • Critical for real-time and large-scale use
  • Excel: GANs, normalizing flows (single forward pass)
  • Struggle: autoregressive, diffusion (sequential steps)

2. High-Quality Sampling

  • Realistic, detailed, indistinguishable from real
  • Excel: modern GANs, diffusion, large autoregressive models
  • Often paid for with compute or training complexity

3. Coverage (Diversity)

  • Generate the full diversity of training data
  • Failure mode: mode collapse (GANs) — limited variety
  • Excel: VAEs (often at the cost of sample quality)

4. Well-Behaved Latent Space

  • Smooth, meaningful structure
  • Similar \(\mathbf{z}\) → similar outputs
  • Enables interpolation and controlled generation
  • Excel: VAEs (explicit training objective)

5. Disentangled Latent Space

  • Different dimensions → independent factors
  • e.g. separate controls for pose, lighting, color
  • Enables fine-grained, interpretable control
  • Hard without explicit architectural design

6. Efficient Likelihood Computation

  • Evaluate \(p_{\theta}(\mathbf{x})\) for any sample
  • Enables direct optimization, anomaly detection, model comparison
  • Have: autoregressive, flows, VAEs (approx)
  • Lack: GANs, many diffusion models

Evaluating Generative Models

Why Evaluation Is Hard

Usually no single correct output. Many outputs may be valid for one input.

Better question than “is it correct?”:

Is the generated image plausible, diverse, useful, and faithful to the condition?

Likelihood

\[\frac{1}{N} \sum_{i=1}^{N} \log p_{\theta}(\mathbf{x}^{(i)})\]

High likelihood → model assigns high probability to real data.

  • Not available for GANs (no explicit density)
  • High likelihood ≠ perceptually good samples

Human Evaluation

  • Which image looks more realistic?
  • Which better matches the prompt?
  • Which has fewer artifacts?
  • Which would you prefer to use?

Most meaningful for visual quality — but slow, subjective, expensive.

Distribution-Level Metrics

Inception Score (IS) (Salimans et al. 2016): classifier-based — confident per-image + diverse across set.

Limitations of Distribution Metrics

  • Depend on a pretrained classifier
  • Most meaningful for class-balanced data (e.g. ImageNet)
  • Don’t compare generated images directly to real images
  • Don’t evaluate prompt adherence or input fidelity
  • Can hide failures on rare classes, spatial relations, text rendering
