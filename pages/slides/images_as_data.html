Learning Objectives

  • Represent images as tensors (H, W, C)
  • Distinguish RGB vs. grayscale
  • Reason about resolution trade-offs
  • Design train / val / test splits and avoid leakage
  • Recognize class imbalance, label noise, hidden biases

Why It Matters

Many classification failures aren’t model failures — they’re data failures.

Imbalance, noisy labels, hidden shortcuts.

Image Representations

Images as Tensors

Figure 1: An image as a tensor of shape H × W × C.

Each pixel holds one or more numeric values per channel.

Pixel Values

  • Stored as 8-bit unsigned int, range \([0, 255]\)
  • Normalized to floats \([0, 1]\) for training
  • Or standardized to zero mean, unit variance

Shape Conventions

  • NumPy / PIL: H × W × C (channels last)
  • PyTorch: C × H × W (channels first)

A 224×224 RGB image:

  • NumPy: (224, 224, 3)
  • PyTorch: (3, 224, 224)

Mismatched conventions → silent bugs.

Quiz: Batch Shape

A batch of 32 RGB images, each 224 × 224, in PyTorch.

What is the tensor shape?

Answer: (32, 3, 224, 224) — batch × channels × height × width

The batch dimension is always first in PyTorch — enables parallel GPU computation.

Quiz: MRI as a Tensor

How would an MRI scan be represented? Does H × W × C still apply?

  • 2-D slice: H × W (or H × W × 1)
  • 3-D volume: D × H × W
  • Multi-sequence (T1, T2, FLAIR, …): D × H × W × C
  • fMRI (time series): T × D × H × W

The H × W × C abstraction generalizes — sequences/depth become extra axes.

Color and Channels

Figure 2: RGB (3 channels) vs. grayscale (1 channel) — same image, different representations.

Channel Counts in the Wild

  • 1: grayscale, depth, thermal/IR, X-ray, ultrasound
  • 3: RGB (also HSV, Lab — same info, different axes)
  • 4: RGBA (alpha) or RGB + near-infrared
  • N (10s–100s): multispectral / hyperspectral (remote sensing, agriculture, astronomy)

Only C changes — the tensor structure stays the same.

Beyond RGB

  • Infrared — thermal imaging, night vision, satellite
  • Depth maps — distance-to-camera per pixel
  • Multispectral / Hyperspectral — narrow wavelength bands
  • HSV — separates hue from brightness; useful for color-based augmentation/segmentation

Resolution

Figure 3: Same image at 224 × 224, 64 × 64, 16 × 16. Detail is progressively lost.

Resolution Trade-offs

  • Higher → preserves detail, costs memory + compute
  • Lower → faster, lighter, but discards information
  • Aspect-ratio distortion → squashing to square deforms objects

Common: resize shortest edge + center-crop, or resize with padding.

Image Datasets

Labels and Classes

Index Class Name
0 empty
1 deer
2 fox
3 badger
4 bird

Example mapping for a camera-trap dataset.

Class Granularity

  • Fine-grained (red deer vs. roe deer) → more data, more ambiguity
  • Coarse (animal vs. empty) → easier, less informative
  • Single-label: exactly one class per image
  • Multi-label: multiple simultaneously (e.g. deer + bird)

Dataset Splits

  • Train — optimize parameters; seen repeatedly
  • Validation — tune hyperparameters, monitor overfitting; never trained on
  • Test — held out for final, unbiased evaluation

Splitting Strategies

  • Random — not always appropriate
  • Stratified — preserve class distribution across splits
  • Grouped — keep related images (same event, patient, location) in the same split

Grouped Splits

Figure 4: Three frames from a single camera-trap trigger event — near-duplicates.

All three must go into the same split.

Data Leakage

Information from val/test inadvertently influences training.

→ Inflated metrics, real-world collapse.

Common Leakage Sources

  • Near-duplicates across splits (camera-trap bursts, video frames)
  • Same subject / location in multiple splits
  • Preprocessing stats computed over the full dataset (not just training)

Quiz: Dermoscopy Splits

500 patients, multiple visits each. Images shuffled and split 80/10/10.

What goes wrong?

Same patient appears in train AND test. The model learns to recognize patients — skin tone, mole patterns, clinic lighting — instead of lesions.

Fix: split at the patient level.

Class Imbalance

Figure 5: Camera-trap class distribution. “Empty” dominates; rare species are scarce.

Consequences of Imbalance

  • Model favors the majority class — minimizes overall loss
  • Rare classes get few gradient updates
  • Accuracy lies — predicting always “empty” can hit 90%

Mitigations

  • Oversample minorities / undersample majorities
  • Weighted loss — penalize errors on rare classes more
  • Better metrics: per-class precision, recall, F1

Label Noise

Figure 6: Wolf or large dog? Empty, or a tail at the edge of the frame?

Sources of Label Noise

  • Inter-annotator disagreement on borderline cases
  • Systematic errors — annotators consistently confuse two classes
  • Ambiguous category boundaries — class definitions overlap

Models first learn clean patterns, then memorize noise (Arpit et al. 2017) — early stopping helps.

Practical takeaway: always inspect the data before training.

Hidden Bias — Cows on Beaches

Figure 7: Same animal, different background → different prediction. The background, not the cow, drives the prediction. Adapted from Beery et al. (2018).

Forms of Hidden Bias

  • Geographic — limited regional diversity (architecture, vegetation, clothing)
  • Selection — internet-sourced images overrepresent certain demographics/styles
  • Watermark / source artifacts — visual quirks correlate with labels

Hard to detect from aggregate metrics — surface only via failure analysis.

Summary

Key Takeaways

  • Images = tensors of shape H × W × C (PyTorch: C × H × W)
  • Resolution is a trade-off — detail vs. compute
  • Splits matter: stratify, group, avoid leakage
  • Imbalance, noise, bias — inspect data before training

The model can only be as good as the data it learns from.
